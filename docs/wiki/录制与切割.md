# 录制与切割

## 捕获模式如何选择

录制主循环会根据**当前选中流的编码/格式**和配置 `flv_native_capture` 决定模式：

| 条件 | 模式 | 说明 |
|------|------|------|
| `flv_native_capture=true` 且 `format=flv` 且 codec 为 `avc/h264` | **native FLV** | HTTP-FLV 直拉 + 原生解析分段写盘 |
| `flv_native_capture=true` 且 非 flv 但 codec 为 `avc/h264` | **FFmpeg FLV bridge** | 单路 FFmpeg 读网流转成 FLV，再走同一套分段管线 |
| 其他 | **FFmpeg 直录** | 传统 FFmpeg 录制流程 |

原生/桥接路径会先写出 `*.capture.flv` 分段，再交给后处理管线。

### FLV 媒体头完整性

- 需要音频时，必须同时收到 AVC 与有效 AAC sequence header，之后才会在下一个视频关键帧创建分段。
- AAC 配置头晚到时，前面的媒体帧会被丢弃，避免生成缺少 `AudioSpecificConfig` 的文件。
- CDN 重连会重新等待媒体头；普通手动/定时切割会复用当前已验证的媒体头。
- 分段日志和 `*.capture.flv.media.json` 会记录 AAC 配置是否存在、声明采样率和配置长度。

## 流选择

全局（可房间覆盖）偏好项包括：

- `stream_resolution`（如 原画）
- `stream_fps` / `stream_bitrate`
- `stream_codec`（`h264` / `hevc` / `av1` 等）
- `stream_format`（`flv` / `fmp4` 等）
- `stream_priority_param`
- `stream_fallback_policy`：`compatible` / `strict` / `best_effort`

默认已从历史 `av1 + fmp4` 迁移到更稳的 **`h264 + flv`**（一次性迁移，用户手改后不会被反复覆盖）。

## 切割规则

可组合使用：

- **按时长**：`split_by_duration`，例如 `01:00:00`
- **按大小**：`split_by_size`，例如 `2GB`
- **事件切割**：标题变化、分区变化、编码变化、流中断等（见配置项）

卡片上也可**手动切割**当前分段。

## 后处理（media pipeline）

分段关闭后异步进入 `media_pipeline`：

1. 健康检查 / 解码校验（可配置严格度）
2. 优先无损 remux（如 `.capture.flv` → `.mp4`）
3. 检查 AAC 配置和音频帧时钟是否与声明采样率一致
4. 在临时文件上完成抽样解码，全部通过后才原子发布最终 MP4
5. 按 `artifact_keep_source` / 旧 `convert_delete_source` 决定是否保留源
6. 成功产物再触发 Webhook 的 split / FileClosed 类事件

缺少 AAC 配置或采样时钟偏差超过 3% 会标记为失败，保留源 FLV，并在
`*.mp4.artifact.json` 写入 `audio_integrity_failed` 的具体原因。

相关配置：

- `artifact_profile`（默认 `lossless_first`）
- `artifact_strict_decode_validation`
- `artifact_keep_source`
- `webhook_only_verified_artifacts`（仅对校验通过的产物发 webhook）
- `convert_enabled` / `convert_format`（遗留键，仍兼容）

## 弹幕

- `chat_record_enabled`
- `chat_format`：如 `jsonl 数据` / xml / ass
- `chat_credential`：需要时填写

弹幕与视频分段独立落盘，便于后期压制或索引。
