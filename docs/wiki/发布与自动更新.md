# 发布与自动更新

## 版本与资产命名

- 代码版本：`version.py` → `__version__`
- Portable 根内：`version.ini`（`version=x.y.z`）
- Release 资产约定（kachina 配置）：
  - 安装包：`dd_rec.Install.${version}.exe`
  - Portable：`dd_rec-${version}-portable.7z`（以实际构建产物为准）

更新通道（`kachina.config.json`）：

- GitHub：`https://github.com/ivanhih/dd-rec/releases/download/...`
- CNB 镜像：`cnb.cool` 发布源

用户配置 `update_channel` 可在 `github` / `cnb` 间选择。

## 用户侧更新流程（Portable / kachina）

1. 启动后异步检查 `releases/latest`
2. 比较 `version.ini` 与远端版本
3. 用户确认后下载更新包
4. 拉起 `dd_rec.update.exe`，主程序退出
5. 更新器替换文件（可走 HDiffPatch）并重启新版本
6. `userdata/` 与 `录播文件/` 默认保留

## 维护者发布检查清单

1. 更新 `version.py`
2. 跑测试
3. `python build.py`
4. 提交并打 tag（建议 `vX.Y.Z` 或与现有历史一致）
5. 创建 GitHub Release，上传安装器与 Portable 资产
6. 用旧版本点“检查更新”做一次冒烟

## 已知限制

- 未签名安装包可能触发 SmartScreen
- 完整包体积较大（含 FFmpeg）
- GitHub API 匿名速率有限；大规模用户可考虑 token/镜像通道
- 当前最新 **代码** 可能新于 GitHub 上已发布的 **Release 包**，以 Release 页面资产为准
