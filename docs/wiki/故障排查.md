# 故障排查

## 先看日志

1. 关于页 → 打开日志 / 日志目录  
2. 或直接查看：

```text
<程序根>/userdata/log/bilirec.log
<程序根>/userdata/log/crash.log
```

反馈 Issue 时请尽量附上日志**尾部**（敏感 Cookie 请打码）。

## 常见问题

### 1. 添加房间失败

- 检查网络与是否能打开直播间页
- 房间号/链接是否正确
- 如遇风控，尝试在房间设置填写有效 SESSDATA

### 2. 一直监控但不录制

- 确认房间监听开关已打开
- 确认主播确实开播
- 检查 `stream_*` 偏好是否过严（`stream_fallback_policy=strict` 时尤其明显）
- 查看日志中的选流结果与错误

### 3. 录制中断 / 文件不完整

- 主播断流、网络抖动会触发重连；原生 FLV 会重置分段避免追加损坏
- `media_stall` / `cdn_failover_slow` 表示媒体进度持续异常，`degraded` 是录制健康状态。通过心跳 `media_speed` 查看近期媒体时间推进速度，约 `1.00x` 表示实时；`speed` 是字节下载速度，两者含义不同。
- 换源后首个可写关键帧只会报告 `media ready`；持续速度验证通过后才会报告 `recovered ... speed_verified=True`。冷却期仍会显示实际异常。
- 已知慢节点会被隔离并延长重试间隔。没有合格替代节点而当前仍有媒体到达时，程序保留当前分段，并记录 `retaining slow source`；不会反复强制切回刚失败的节点。
- 分段媒体清单、产物清单和录制历史可保存连续性诊断。`media_progress_gap_ms` 是分段墙钟时间与媒体时长的差值，不是精确的直播内容丢失时长；文件转换成功也不代表录制期间没有慢流或断档。
- 跨分段等待新媒体的空档保存为 `transport_gaps`；会话 `.session.jsonl` 保留空档起止和恢复验证结果，包括断流期间停止且未生成新分段的情况。
- 检查磁盘空间与杀毒软件是否锁文件
- 查看是否有对应 `.bridge.ffmpeg.log` / ffmpeg 日志

### 4. 有 `.capture.flv` 但没有最终 mp4

- 后处理异步进行，稍等再看
- 检查 `media_pipeline` 相关日志与校验失败原因
- 确认 FFmpeg 可用（打包版应内嵌于 `ffmpeg/`）

### 5. 多房间启动崩溃 / SSL 相关

1.0.5 起使用进程级共享 SSL 上下文，修复 Windows 上多房间并发初始化的 access violation。若仍复现：

- 附上 `crash.log`
- 说明房间数量与是否代理

### 6. 长时间录制后界面卡死/崩溃

1.0.5 将录制线程 UI 状态更新改为队列连接（主线程刷新）。请升级到含该修复的构建。

### 7. 更新失败

- 检查能否访问 GitHub Releases（或切换 `update_channel` 到 `cnb`）
- 确认存在内嵌更新器 `dd_rec.update.exe`
- 杀毒软件是否隔离了更新器/安装器
- 查看 `%TEMP%` 是否有未完成下载包

### 8. SmartScreen / 杀毒误报

未代码签名时较常见。请从官方 Release 下载，并对照资产文件名：

- `dd_rec.Install.<ver>.exe`
- `dd_rec-<ver>-portable.7z`
