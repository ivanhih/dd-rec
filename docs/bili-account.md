# 扫码登录与录制账号

登录是可选功能。不登录时仍按平台允许的匿名权限录制公开直播；可用画质及特殊直播的访问权限由 B站决定。

## 操作

1. 打开“全局设置 → B站账号 → 扫码登录”。
2. 使用哔哩哔哩 App 扫描二维码，并在手机上确认登录。
3. 登录成功后显示用户名、UID 和登录状态，可检查状态或退出账号。
4. 没有手填凭据的房间及新房间自动使用全局账号。点击“全部房间使用此账号”可以切换所有已有房间；旧手填凭据保留。

侧边栏顶部也提供账号入口：未登录时显示默认头像和“登录”，点击直接打开扫码界面；登录后显示用户头像，点击进入账号设置。退出或账号失效后恢复登录按钮。头像获取失败时显示默认头像，仍可使用账号入口。

二维码支持等待扫码、手机待确认、过期、刷新、取消。网络请求在后台执行，取消或刷新后旧结果不会写入账号。
扫码界面会说明登录用于请求账号有权访问的直播画质和弹幕数据，登录是可选的，并明确登录信息只在本机保存、不向 DD 服务器同步；访问 B站时会发送必要的登录凭据。
扫码界面和房间设置、手填 Cookie 一样，使用主窗口内的 overlay 遮罩层；点遮罩、关闭按钮、取消或按 Esc 都可退出扫码。

## 房间选择

房间设置中的“录制账号”统一控制直播 API、视频拉流和弹幕请求。

| 选项 | 行为 |
| --- | --- |
| 默认（手填优先） | 房间手填 Cookie 优先；否则使用全局账号；均未设置则匿名。保留已有弹幕凭据覆盖。 |
| 全局扫码账号 | 使用当前全局账号；未登录或失效则匿名，不使用房间旧手填凭据。 |
| 匿名录制 | 不发送账号 Cookie，包括视频和弹幕。 |
| 仅手填 Cookie | 只使用该房间手填凭据；留空则匿名，不使用全局扫码账号。 |

登录、退出和模式切换会在后续请求或重连时生效，不主动中断健康的录制连接。
FFmpeg 的 HLS 清单、分片、密钥和初始化文件经过仅监听本机的媒体转发，逐次读取最新凭据。
账号 Cookie 不进入 FFmpeg 命令行；上游媒体请求保留房间代理设置。

## 账号保存与维护

账号 Cookie、刷新令牌和用户信息保存在 `userdata/bili_account.json`，当前为本机 JSON 明文存储，不上传到其他项目，也不写入 Git。
请勿分享这个文件或整个 `userdata` 文件夹。退出账号清空本地保存的登录信息；不调用平台注销接口。

程序运行期间定期检查账号，在 B站要求更新时执行 Web Cookie 刷新。明确登录失效后默认账号回退匿名并提示重新扫码；网络错误不会删除登录信息。
“检查登录状态”可以立即触发检查。刷新后的新凭据先原子保存，再确认旧刷新令牌，防止网络失败丢失新凭据。

该实现独立使用 B站 Web 扫码接口，无需启动 biliupforjava。已有录制事件 Webhook 对接保持兼容。

## 验证范围

自动测试覆盖凭据优先级、匿名隔离、二维码取消/刷新竞态、账号保存与失效、刷新流程、Qt 主线程更新及媒体重连。
真实匿名接口已验证可以生成二维码并返回等待扫码；本地 HLS 已通过内置 FFmpeg 实际读取验证。
真实账号的手机确认、长期 Cookie 刷新及平台授权画质仍需使用账号进行联调。
